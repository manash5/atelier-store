# Database design

The database is Neon PostgreSQL, accessed through Drizzle ORM with the node-postgres driver. The backend owns everything database-related:

| What | Where |
|---|---|
| Connection | `backend/src/database/index.ts` (pg `Pool`, size `DATABASE_POOL_MAX`) |
| Schema | `backend/src/database/schema/` (`catalog.ts`, generated `auth.ts`, `index.ts` re-exports both) |
| Migrations | `backend/src/database/migrations/` (generated SQL, committed) |
| Seed | `backend/src/database/seed/` (`seed.ts`, `data/catalog.ts`) |
| drizzle-kit config | `backend/drizzle.config.ts` |

## Catalog tables

```
categories 1 ──── n products
```

**categories**

| Column | Type | Notes |
|---|---|---|
| id | integer identity PK | |
| slug | text, unique | |
| title | text | |
| image | jsonb, nullable | `{ src, alt, position? }`. Categories without an image are hidden from the homepage grid |
| sort_order | integer, default 0 | display order |
| created_at, updated_at | timestamptz | |

**products**

| Column | Type | Notes |
|---|---|---|
| id | integer identity PK | insertion order = catalog order |
| slug | text, unique | |
| category_id | integer → categories.id | `ON DELETE RESTRICT`, indexed |
| name | text | |
| style_number | text, unique | exposed as `styleNumber` / JSON-LD `sku` |
| price | integer, `CHECK (price >= 0)` | **minor units** (cents) |
| currency | text, default `'USD'` | ISO 4217 |
| color_name, color_hex | text | |
| stock | integer, default 0, `CHECK (stock >= 0)` | units available. Status is derived, never stored |
| description | text | |
| details | text[] | ordered bullet points |
| images | jsonb, `CHECK` non-empty array | ordered; `[0]` is the listing image |
| badge | enum `product_badge` (`New`, `Limited`), nullable | |
| created_at, updated_at | timestamptz | |

The tables deliberately exclude carts, orders, payments, reviews, wishlists and product variants. When variants arrive, `stock` (and probably `price`) moves to a `product_variants` table.

## Auth tables

`user`, `session`, `account` and `verification` are generated by the Better Auth CLI into `schema/auth.ts`. Don't edit that file by hand.

## Migrations

The history starts at `0000_catalog` (catalog tables) followed by `0001_auth` (Better Auth tables). There were no migrations before the frontend/backend split.

Workflow (in `backend/`):

```bash
# 1. Edit backend/src/database/schema/*.ts
npm run db:generate         # writes the next SQL file; review it and commit it
npm run db:migrate          # applies pending migrations to DATABASE_URL
npm run db:seed             # optional: idempotent sample catalog
```

After changing the Better Auth config (providers, plugins), run `npm run auth:generate` first, then `db:generate`.

Rules:
- Use versioned migrations only. Don't run `drizzle-kit push` against shared, preview or production databases.
- Before the first `db:migrate` on an existing Neon database, check that it is empty (`npm run db:studio`). If the old app ever used `db:push`, migrate a fresh Neon branch instead.
- CI or the deploy pipeline runs `db:migrate` before deploying the backend.

## Seed

- `npm run db:seed` upserts 5 categories and 12 products by `slug` inside one transaction.
- Re-running it updates rows in place and never deletes.
- The seed data keeps prices in whole units for readability and converts them to cents on insert.
- Use only unbranded images (no visible logos or labels).
