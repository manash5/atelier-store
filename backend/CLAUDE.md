# CLAUDE.md (backend)

This is the Express 5 REST API: TypeScript (ESM), Drizzle ORM on node-postgres, Neon PostgreSQL, Zod and Better Auth. Architecture: `../docs/architecture/backend-architecture.md`. Database: `../docs/database/database-design.md`.

## Commands

- `npm run dev` (tsx watch, :4000), `npm run build` (tsup → `dist/server.js`), `npm start`, `npm run typecheck`, `npm run lint`
- `npm test` (Vitest). API tests that need data run only when `TEST_DATABASE_URL` points at a migrated, seeded, **non-production** database.
- `npm run db:generate`, `db:migrate`, `db:seed`, `db:studio`, `auth:generate`

## Layer rules (ESLint-enforced)

- Requests flow **routes → controllers → services → repositories → database**. Never import upward.
- **Routes:** attach `validate({ params, query, body })` with Zod schemas from `src/dtos/`, then bind a controller.
- **Controllers:**
  - Read input with `validated(req, part, Schema)`, call one service method, map with `dtos/*` mappers, respond with `sendOk`.
  - No business logic, no DB access, no `try/catch`: Express 5 forwards async errors.
- **Services:**
  - Hold all business rules.
  - Throw `AppError` subclasses from `exceptions/`.
  - Never import Express, Drizzle or `database/`.
- **Repositories:** Drizzle queries only; return models, arrays or `null`. Never handle HTTP or throw HTTP errors.
- **Models:** derive types from the schema (`$inferSelect`) instead of redefining columns. Domain rules such as `deriveStockStatus` live here.
- **Errors:** every error response uses the envelope `{ error: { code, message, details? } }`, produced only by `middleware/error-handler.ts`.

## Conventions

- `process.env` is read **only** in `src/config/env.ts` (Zod-validated). Add new variables there, and to `.env.example` and `docs/architecture/overview.md`.
- Better Auth (`src/lib/auth.ts`) is mounted at `/api/auth/*` **before** `express.json()`. Keep it that way.
- Protect `/api/v1` routes with `authorize` (Bearer JWT → `req.user`) and `authorizeAdmin` from `middleware/auth.middleware.ts`; put `uploadImage` (`middleware/upload.middleware.ts`) after them. Session cookies only authenticate `/api/auth/*`.
- Admin features go on `adminRouter` (`routes/admin.routes.ts`), which already applies `authorize`, `authorizeAdmin` (role re-checked in the database) and `auditAdminWrites`. Don't re-enable Better Auth's `/api/auth/admin/*` endpoints (ADR-016).
- Stock changes only through `orderRepository.placeFromCart` (checkout), `adminOrderRepository.transition` (cancel restock) and `adminCatalogRepository.setStock` (optimistic). Order status changes must go through `ORDER_TRANSITIONS` in `models/order.ts`.
- Public write endpoints need a rate limiter (see `appointmentRateLimit` in `middleware/rate-limit.ts`) and should return receipts, not stored personal data. Use `optionalAuthorize` when signed-in users may optionally be linked (ADR-017).
- `npm run db:seed` only inserts missing rows; `-- --reset` overwrites seeded rows (development only).
- `src/database/schema/auth.ts` is generated by `npm run auth:generate`. Never edit it, and keep app tables in their own schema files exported from `schema/index.ts`.
- Use `db.transaction()` for multi-row writes. Never build SQL from strings; use Drizzle's query builder or the `sql` template.
- Prices are integer minor units, and stock status is derived, never stored.
- Carts and orders exist (ADR-015): stock is checked when items are added and again atomically when an order is placed. Payments are simulated: only the card's last four digits reach the backend.
- Don't add real payments, reviews, wishlists or variants without an approved design update.
- `clients/` holds third-party API wrappers and `cron/` holds scheduled jobs (both empty for now).
